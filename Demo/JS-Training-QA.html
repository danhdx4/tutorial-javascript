🤔 Node.js là gì?

🖥️ Trước đây

JavaScript chỉ chạy được trên trình duyệt (Chrome, Firefox…)
Không thể chạy trên máy tính độc lập.

🚀 Với Node.js

JavaScript chạy được trực tiếp trên máy tính — không cần trình duyệt.
Đây là nền tảng để chạy Playwright, Cypress, v.v.

💡
Hãy nghĩ Node.js như "máy chạy JavaScript" được cài trên máy tính của bạn.

⚙️ npm là gì?

npm (Node Package Manager) được cài kèm Node.js tự động.
Dùng để tải thư viện (Playwright, Axios…) chỉ bằng một lệnh.

🎯 Tại sao QA cần Node.js?

  • Chạy Playwright / Cypress
  • Chạy script automation test
  • Tải các thư viện test
  • Chạy file .js từ terminal

📥 Cài đặt Node.js (mọi hệ điều hành)

1

Truy cập trang chính thức

Mở trình duyệt → vào nodejs.org → chọn nút "LTS" (Long Term Support) — đây là phiên bản ổn định nhất.

2

Tải file cài đặt phù hợp hệ điều hành

Windows: tải file .msi → chạy → Next → Next → Install
macOS: tải file .pkg → chạy → Continue → Install
Linux (Ubuntu): dùng lệnh terminal bên dưới

3

Kiểm tra cài đặt thành công

Mở Terminal / Command Prompt → gõ lệnh kiểm tra: 

# Kiểm tra Node.js đã được cài chưa
node --version
# Kết quả ví dụ: v22.x.x  ← phiên bản hiện tại

# Kiểm tra npm
npm --version
# Kết quả ví dụ: 10.x.x

🎯 Mục tiêu + Function là gì?

🎯 Sau buổi này bạn sẽ:

  • Hiểu Function là gì, dùng để làm gì
  • Viết được Function Declaration

🔧 Function là gì?

Function = một khối code có thể tái sử dụng

💡 Đơn giản: Input → Xử lý → Output

Ví dụ cơ bản nhất:

// Định nghĩa function
function sayHello() {
  console.log("Hello!");
}

// Gọi function — dùng lại bao nhiêu lần cũng được
sayHello(); // Hello!
sayHello(); // Hello!
sayHello(); // Hello!
💡
Thay vì copy-paste code nhiều lần, đặt nó vào 1 function → gọi bao nhiêu lần cũng được mà chỉ cần sửa ở 1 chỗ!
Function · Declaration
Buổi 5

🔧 Function Declaration

📝 Cú pháp

function tenFunction(param1, param2) {
  // logic xử lý
  return ketQua;
}

Demo với tham số:

function greet(name) {
  console.log(`Hello ${name}!`);
}

greet("Danh"); // Hello Danh!
greet("An");   // Hello An!

Có return value:

function add(a, b) {
  return a + b;
}
console.log(add(3, 5)); // 8

⚠️ Điểm đặc biệt: Hoisting

Function Declaration có thể gọi trước khi khai báo — JavaScript tự "kéo" nó lên đầu file. 

// ✅ Hợp lệ — gọi TRƯỚC khi khai báo!
sayHi();

function sayHi() {
  console.log("Hi!");
}
// Output: Hi!
💡
Hoisting = JavaScript đọc qua file một lần để "nhặt" tất cả Function Declaration lên đầu trước khi thực sự chạy code.
Function · Arrow Function
Buổi 5

➡️ Arrow Function (ES6 — cách hiện đại)

📝 Cú pháp

const tenFunction = (param1, param2) => {
  // logic
  return ketQua;
};

Demo tương đương Function Declaration:

// Arrow Function
const greet = (name) => {
  console.log(`Hello ${name}!`);
};

greet("Danh"); // Hello Danh!

✂️ Viết gọn hơn

Nếu chỉ có 1 dòng lệnh, có thể bỏ { } và return: 

// 1 dòng — bỏ return và { }
const sum = (a, b) => a + b;

// 1 tham số — bỏ luôn ( )
const greet = name => `Hello ${name}`;

// Không tham số — giữ ( )
const sayHi = () => "Hi!";

console.log(sum(3, 4));      // 7
console.log(greet("An"));  // Hello An
console.log(sayHi());      // Hi!
⚠️
Arrow Function không có Hoisting — phải khai báo trước khi gọi!
Function · So sánh & Demo
Buổi 5

⚖️ So sánh nhanh + Demo thực tế

Function Declaration Arrow Function
Hoisting ✅ Có ❌ Không
Syntax Dài hơn Ngắn hơn
Dùng khi Logic chính Callback, code ngắn
💡
Trong thực tế, cả hai đều dùng được. Arrow Function ngày càng phổ biến hơn nhờ cú pháp ngắn gọn.

Demo: Kiểm tra số chẵn

// Cách 1: Function Declaration
function isEven(n) {
  return n % 2 === 0;
}

// Cách 2: Arrow Function (ngắn hơn)
const isEven = n => n % 2 === 0;

// Kết quả giống nhau!
console.log(isEven(4)); // true
console.log(isEven(5)); // false
🎯
n % 2 = phép chia lấy phần dư. Số chẵn chia 2 dư 0, số lẻ dư 1.

✏️ Bài tập đơn giản — Function & Arrow Function

📚 Bài 1 — Tính tổng

Viết function declaration nhận 2 số, trả về tổng. 

// Kết quả mong đợi:
tinhTong(3, 7);  // 10

📚 Bài 2 — Diện tích hình chữ nhật

Viết arrow function nhận width, height, trả về diện tích. 

// Kết quả mong đợi:
dienTich(5, 4); // 20
dienTich(3, 3); // 9

📚 Bài 3 — Chẵn hay Lẻ?

Viết arrow function nhận 1 số, trả về chuỗi "Chẵn" hoặc "Lẻ". 

// Kết quả mong đợi:
chanLe(4); // "Chẵn"
chanLe(7); // "Lẻ"

📚 Bài 4 — Lời chào cá nhân hoá

Viết function declaration nhận name và role, in ra lời chào. 

// Kết quả mong đợi:
chaoMung("An", "QA");
// "Chào An! Vai trò của bạn là QA."

📚 Bài 5 — Tìm số lớn nhất

Viết arrow function nhận mảng số, trả về số lớn nhất. (Gợi ý: dùng Math.max(...arr)) 

// Kết quả mong đợi:
timMax([3, 9, 1, 7]); // 9
timMax([-2, 0, 5]);   // 5
💡
Mỗi bài hãy thử viết cả 2 cách: function declaration và arrow function để so sánh!

const divide = (a, b) => a / b;

const numbers = [1,2,3,4];
// 👉 Tạo array bình phương các số

❌ Lỗi hay gặp: Quên return

// ❌ Sai — không có return, kết quả bị bỏ đi
const sum = (a, b) => {

console.log(sum(1, 2)); // undefined !

// ✅ Cách 1: thêm return
const sum = (a, b) => {

const sum = (a, b) => a + b;

🧠 Array và Object là gì?

📋 Array — Danh sách

Dùng khi cần lưu nhiều phần tử cùng loại theo thứ tự. 

const users = ["An", "Bình", "Cường"];

// Truy cập bằng index (bắt đầu từ 0)
users[0]; // "An"
users[1]; // "Bình"

📦 Object — Đối tượng

Dùng khi cần mô tả một thứ với nhiều thuộc tính (key-value). 

const user = {
  name: "An",
  age:  25
};

// Truy cập bằng key
user.name; // "An"
user.age;  // 25
Array Object
Dùng khi Danh sách nhiều thứ 1 đối tượng
Truy cập index [0] key .name
Ví dụ List users 1 user
🎯
Thực tế hay gặp nhất: Array of Objects — đây chính xác là format JSON mà API trả về! 
// Array of Objects — format API phổ biến nhất
const users = [
  { name: "An",   age: 25 },
  { name: "Bình", age: 30 }
];
Array Methods · map()
Buổi 6

🟢 map() — Biến đổi toàn bộ Array

🟢 Dùng khi nào?

Muốn tạo array mới bằng cách biến đổi từng phần tử của array cũ.

📌 Array gốc không bị thay đổi.

Ví dụ cơ bản:

const numbers = [1, 2, 3];

const doubled = numbers.map(n => n * 2);

console.log(doubled); // [2, 4, 6]
console.log(numbers); // [1, 2, 3] ← không đổi!

Ví dụ thực tế — lấy danh sách name từ API:

const users = [
  { name: "An",   age: 25 },
  { name: "Bình", age: 30 }
];

const names = users.map(u => u.name);

console.log(names);
// ["An", "Bình"]
🔗
Trong API Testing: Nhận list orders từ API, dùng map() để lấy danh sách id hoặc status để verify — rất thường dùng!
Array Methods · filter() & find()
Buổi 6

🔵 filter() và 🟣 find()

🔵 filter() — Lọc nhiều kết quả

Lấy ra tất cả phần tử thỏa điều kiện → trả về Array mới. 

const users = [
  { name: "An",    age: 25 },
  { name: "Bình",  age: 30 },
  { name: "Cường", age: 20 }
];

const adults = users.filter(u => u.age >= 25);

console.log(adults);
// [{ name:"An",age:25 }, { name:"Bình",age:30 }]

🟣 find() — Tìm 1 kết quả đầu tiên

Lấy ra phần tử đầu tiên thỏa điều kiện → trả về 1 object hoặc undefined. 

const user = users.find(u => u.name === "Bình");

console.log(user);
// { name: "Bình", age: 30 }

// ⚠️ Cẩn thận: có thể trả undefined!
const notFound = users.find(u => u.name === "XYZ");
console.log(notFound); // undefined

// ✅ Luôn kiểm tra trước khi dùng
if (user) {
  console.log(user.name);
}
Array Methods · So sánh & Kết hợp
Buổi 6

⚠️ So sánh map / filter / find + Kết hợp

Method Dùng khi Trả về
map() Biến đổi tất cả Array mới
filter() Lọc nhiều kết quả Array mới
find() Tìm 1 phần tử 1 object / undefined
✅
Cả 3 method đều KHÔNG thay đổi array gốc — dùng thoải mái mà không sợ mất dữ liệu.
⚠️
Luôn kiểm tra find() có trả undefined không trước khi truy cập property — đây là lỗi rất hay gặp!

🔁 Kết hợp nhiều method (method chaining)

const orders = [
  { id:1, status:"success", total:100 },
  { id:2, status:"pending", total:200 },
  { id:3, status:"success", total:150 }
];

// Lấy tổng tiền các order "success"
const totals = orders
  .filter(o => o.status === "success")
  .map(o => o.total);

console.log(totals); // [100, 150]

🔤 Template Literal là gì?

Template Literal cho phép bạn nhúng biến trực tiếp vào chuỗi mà không cần dùng dấu +.
Được bao bởi dấu backtick ( ` ) thay vì dấu nháy thường.

❌ Cách cũ — khó đọc

const name = "Lan";
const age = 25;
console.log("Tôi là " + name + ", " + age + " tuổi");
// 👆 Dễ nhầm lẫn, khó bảo trì

✅ Template Literal — rõ ràng

const name = "Lan";
const age = 25;
console.log(`Tôi là ${name}, ${age} tuổi`);
// ✅ Sạch hơn, dễ đọc hơn nhiều!

🔑 Cú pháp cơ bản

  • Dùng dấu backtick ` bao quanh chuỗi
  • Dùng ${ } để nhúng biến hoặc biểu thức
  • Hỗ trợ viết nhiều dòng tự nhiên
⚠️
Dấu ` (backtick) khác với dấu nháy đơn '. Thường ở góc trái trên bàn phím (cạnh số 1).

🏛️ Class là gì? Tại sao cần dùng?

🍪 Hãy nghĩ như khuôn bánh

Class = khuôn bánh (bản thiết kế)
Object = chiếc bánh được tạo ra từ khuôn

Một khuôn có thể tạo ra nhiều chiếc bánh khác nhau (mỗi cái có nhân khác nhau).

🎯 Lợi ích trong Testing

  • Nhóm các hàm liên quan vào một chỗ
  • Tái sử dụng code cho nhiều test case
  • Dễ bảo trì khi thay đổi
💡
Trong framework Playwright, bạn thường tạo Page Object — đó chính là một Class!

Cấu trúc cơ bản một Class:

class TenClass {

  // constructor: chạy khi tạo object mới
  constructor(thamSo1, thamSo2) {
    this.thamSo1 = thamSo1;
    this.thamSo2 = thamSo2;
  }

  // method: hàm bên trong class
  tenHam() {
    console.log(`Hello ${this.thamSo1}`);
  }
}

// Tạo object từ class
const obj = new TenClass("giaTri1", "giaTri2");

📝 Class thực tế — Page Object cho Login

Tạo LoginPage class:

// file: LoginPage.js
class LoginPage {

  constructor(username, password) {
    this.username = username;
    this.password = password;
    this.loginCount = 0;
  }

  login() {
    this.loginCount++;
    console.log(
      `Đăng nhập với: ${this.username}`
    );
  }

  getInfo() {

      `User: ${this.username},

🧬 Kế thừa Class — extends

🧬 Kế thừa là gì?

Class con thừa hưởng tất cả thuộc tính và method của class cha, đồng thời có thể thêm mới hoặc ghi đè. 

// Class CHA — dùng chung
class BasePage {
  constructor(url) {
    this.url = url;
  }
  navigate() {
    console.log(`Mở trang: ${this.url}`);
  }
}
// Class CON — kế thừa từ BasePage
class LoginPage extends BasePage {

  constructor(url, username) {
    super(url); // gọi constructor của class cha
    this.username = username;
  }

  login() {
    this.navigate(); // dùng method của class cha
    console.log(`Login: ${this.username}`);
  }
}

const page = new LoginPage(
  "https://example.com/login", "admin"
);
page.login();
// Mở trang: https://example.com/login
// Login: admin
🎯
super() = "gọi constructor của class cha". Phải gọi trước khi dùng this trong class con.

📌 Class — Những điều cần nhớ cho QA

🔑 Cú pháp cơ bản

  • class Tên { } — luôn viết hoa chữ cái đầu
  • constructor() — hàm chạy khi new
  • this.xxx — thuộc tính của object đó
  • new Tên() — tạo instance mới

📦 Methods hay dùng trong test

  • getInfo() — in thông tin đẹp (template literal)
  • toJSON() — biến thành plain object để gửi API
  • static fromJSON(data) — tạo instance từ response API
  • isAdmin() — kiểm tra role/permission

🔗 Kế thừa (extends)

  • class Con extends Cha — kế thừa toàn bộ
  • super() — gọi constructor cha, bắt buộc viết trước this
  • Class con có thể thêm method riêng hoặc override method cha

❌ Lỗi hay gặp

  • Quên new → TypeError
  • Quên this. → biến không lưu được
  • Quên super() trong class con → lỗi ngay
  • Gọi static method trên instance → sai, phải gọi trên class

🎯 Khi nào QA cần dùng Class?

  • Page Object Model — mỗi trang = 1 class
  • Test Data — tạo User, Product từ JSON
  • API Helper — class chứa các hàm gọi API
  • Store/Service — quản lý danh sách dữ liệu
💡
Quy tắc nhớ: Class = khuôn bánh, Instance = chiếc bánh. Một khuôn tạo được nhiều bánh. Mỗi bánh có nhân riêng (constructor) nhưng cùng hình dáng (methods).

Buổi 8

⚡ Async là gì? Tại sao cần "chờ"?

☕ Ví dụ đời thực

Bạn gọi nước tại quán:
1️⃣ Bạn: "Cho tôi 1 cà phê"
2️⃣ Nhân viên: "Vâng, chờ tôi 5 phút"
3️⃣ Bạn: Chờ... (không thể kiểm tra nước đã xong chưa nếu không chờ)
4️⃣ Nhân viên: "Xong, đây là cà phê"
5️⃣ Bạn: Uống ☕

⚠️ Nếu bạn không chờ: chạy ra khỏi quán lúc nhân viên đang pha → không có nước!

💻 Trong Testing (Playwright)

Giống như quán nước:
1️⃣ Test: "Gọi API lấy users"
2️⃣ Server: "Đang xử lý..."
3️⃣ Test: PHẢI CHỜ await
4️⃣ Server: "Đây là danh sách users"
5️⃣ Test: Kiểm tra dữ liệu ✅

❌ Nếu bỏ await: Test kiểm tra ngay lập tức, server chưa trả dữ liệu → test sai!

Khi nào cần await? (Đặc biệt trong Playwright)

Tác vụ Cần await? Lý do
await page.goto() ✅ Chờ page load xong
await page.click() ✅ Chờ action hoàn tất
await fetch(url) ✅ Chờ response từ server
const x = 1 + 1 ❌ Ngay lập tức, không chờ

🎯 Điểm mấu chốt

Có await:

const data = await fetch(url);  // ✅ Chờ
console.log(data);  // ✅ Data đã sẵn sàng

Không await:

const data = fetch(url);  // ❌ Không chờ
console.log(data);  // ❌ Promise, không phải dữ liệu!

📝 Cú pháp async / await

Cấu trúc cơ bản (gọi API thật):

// "async" trước function = function này có thể chờ
async function layDuLieu() {

  console.log("Bắt đầu gọi API...");

  // "await" = chờ kết quả trước khi tiếp tục
  const response = await fetch(
    "https://products-api-ten-alpha.vercel.app/api/products"
  );

  const data = await response.json();

  console.log(`Số sản phẩm: ${data.length}`);
}

// Gọi function async
layDuLieu();
🌐
API này đang chạy thật trên Vercel: https://products-api-ten-alpha.vercel.app/api/products — trả về 3 sản phẩm JSON.

📌 Quy tắc vàng

  • async đặt trước từ khóa function
  • await chỉ dùng được bên trong hàm async
  • Mỗi bước "chờ" đặt một await

🔄 Arrow function cũng dùng được

const layDuLieu = async () => {
  const data = await fetch(url);
  return data;
};
💡
Trong Playwright, hầu hết các hành động đều cần await: click, type, navigate, screenshot…

🌐 Ví dụ gọi API thật — có delay 4 giây

Gọi API chi tiết sản phẩm (server cố tình delay 4s):

async function layChiTiet(id) {
  console.log("⏳ Bắt đầu gọi API...");

  const res = await fetch(
    `https://products-api-ten-alpha.vercel.app
/api/products/${id}`
  );
  const data = await res.json();

  console.log("✅ Đã có dữ liệu:", data);
}

layChiTiet(2);

✅ Khi chạy

⏳ Bắt đầu gọi API...
→ chờ ~4 giây (server delay thật)
→ ✅ Đã có dữ liệu: { id: 2, name: "iPhone 15 Pro", ... }

❌ Nếu bỏ await

res sẽ là Promise { <pending> }, không phải data → gọi .json() sẽ lỗi ngay. Đây chính là lỗi phổ biến nhất khi viết test API.

💡
Vì sao API có delay 4s? Để bạn cảm nhận rõ sự khác biệt giữa có await (chờ đủ) và không có await (chạy tiếp ngay → sai data).

🛡️ Xử lý lỗi với try / catch

❌ Không có xử lý lỗi

Nếu API lỗi hoặc mất mạng → chương trình crash ngay, không biết lý do tại sao. 

// ❌ Không an toàn
async function test() {
  const data = await fetch("bad-url");
  // 💥 Crash nếu bad-url không tồn tại
}

✅ Có xử lý lỗi — try/catch

try: thử chạy code
catch: nếu có lỗi → bắt lấy và xử lý 

async function goiApi(url) {
  try {
    const response = await fetch(url);
    const data = await response.json();
    console.log("✅ Thành công:", data);
    return data;
  } catch (error) {
    console.log(`❌ Lỗi: ${error.message}`);
    // Không crash, xử lý gracefully
  }
}

// URL sai → catch sẽ bắt được lỗi
goiApi("https://products-api-ten-alpha.vercel.app/api/products/999");
